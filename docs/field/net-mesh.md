# Optional mesh variant: 802.11s + batman-adv

The single-AP design in [net-network.md](net-network.md) covers roughly 100–150 m of woodland
from a router carried at the centre of the squad. A mesh is worth its cost only when the squad
spreads further than that, or works around buildings that shadow the router. The cost is that
every mesh hop retransmits each frame and adds its airtime again.

## Layout

```
   operator Wi-Fi (AP, same SSID on every mesh node, 2.4 GHz ch 6)
        │                    │                    │
  ┌─────┴─────┐  802.11s  ┌──┴────────┐  802.11s  ┌┴──────────┐
  │ router A  │◄────────►│ router B  │◄────────►│ router C  │   backhaul: 5 GHz ch 36/40/44/48 HT40/VHT40,
  │ gw, DHCP, │  bat0     │ bat0      │  bat0     │ bat0      │   or a 2nd 2.4 GHz radio
  │ relay     │           │ relay2    │           │           │
  └───────────┘           └───────────┘           └───────────┘
```

* Mesh nodes are **routers carried by squad members** (two or three GL-MT3000s), not the
  headsets. NetworkManager's 802.11s support on Jetsons is immature, and meshing on the headset
  radio would split one radio's airtime between client and backhaul traffic.
* The **backhaul runs on 5 GHz** (dual-band routers), so mesh retransmissions do not consume the
  2.4 GHz airtime the headsets use.
* **batman-adv** runs over the 802.11s link (`mesh_fwding 0`, so 802.11s does not route as well)
  and bridges `bat0` into `br-lan`. The whole mesh is one L2 segment: DHCP, the UDP beacon, mDNS
  and the relay all work unchanged.
* Only router A runs DHCP. The others set `dhcp.lan.ignore=1` and use a static LAN address
  (`.2`, `.3`). Every node announces the same SSID and passphrase so headsets roam. Because
  `disassoc_low_ack 0` is set, the client's own roaming decides when it moves.
* The primary relay stays on router A. Router B can run `--role secondary --upstream
  ws://relay.lynx:8765` instead of the leader Jetson.

## Packages (each mesh router, once, with internet)

```sh
opkg update
opkg remove wpad-basic-mbedtls wpad-basic-wolfssl 2>/dev/null || true
opkg install wpad-mesh-mbedtls kmod-batman-adv batctl-default
```

`wpad-mesh-*` provides SAE for an encrypted mesh, and `batctl` is for diagnostics.

## UCI (router B shown; change the LAN address per node)

```sh
# 5 GHz radio as the encrypted 802.11s backhaul
uci set wireless.radio1.channel='36'
uci set wireless.radio1.htmode='HE40'           # or VHT40 / HT40 on older radios
uci set wireless.radio1.country='GB'
uci set wireless.radio1.disabled='0'
uci set wireless.mesh0=wifi-iface
uci set wireless.mesh0.device='radio1'
uci set wireless.mesh0.mode='mesh'
uci set wireless.mesh0.mesh_id='lynx-mesh'
uci set wireless.mesh0.encryption='sae'
uci set wireless.mesh0.key='another-long-mesh-passphrase'
uci set wireless.mesh0.mesh_fwding='0'          # batman-adv routes, not 802.11s
uci set wireless.mesh0.mesh_rssi_threshold='-80'
uci set wireless.mesh0.network='bat_hard'

# batman-adv: hard interface on the mesh, bat0 bridged into the LAN
uci set network.bat0=interface
uci set network.bat0.proto='batadv'
uci set network.bat0.routing_algo='BATMAN_IV'
uci set network.bat0.gw_mode='off'
uci set network.bat0.hop_penalty='30'           # prefer fewer hops: each hop costs airtime
uci set network.bat0.orig_interval='1000'
uci set network.bat_hard=interface
uci set network.bat_hard.proto='batadv_hardif'
uci set network.bat_hard.master='bat0'
uci set network.bat_hard.mtu='1536'             # 1500 + batman-adv header, no fragmentation
uci add_list network.@device[0].ports='bat0'    # br-lan (OpenWrt 21.02+ device syntax)

# non-gateway node: no DHCP, static LAN address, router A as gateway/DNS
uci set network.lan.ipaddr='192.168.8.2'
uci set network.lan.gateway='192.168.8.1'
uci add_list network.lan.dns='192.168.8.1'
uci set dhcp.lan.ignore='1'
uci commit
wifi reload; /etc/init.d/network reload
```

On router A, keep DHCP and DNS as generated by `lynx-field netconfig` and add the same `mesh0`,
`bat0` and `bat_hard` sections. The 2.4 GHz client AP from the generated script (`wireless.lynx`)
is identical on every node.

Check the mesh with `batctl n` (neighbours with link quality), `batctl o` (originators and next
hops) and `batctl tp <mac>` (throughput).

## Airtime with a mesh

A frame from a headset attached to router C to the relay on router A crosses the air three times:
the C client AP on 2.4 GHz, then the C→B and B→A backhaul hops on 5 GHz. The 2.4 GHz load per AP
falls, because each AP serves only its own clients. The backhaul carries everyone's traffic once
per hop:

* use the field relay's tick batching (`--tick-ms 25`), which matters even more here because it
  cuts the per-frame overhead on every hop;
* plan at most 2 backhaul hops to the relay;
* `lynx-field bandwidth` gives the per-hop airtime for one cell. Multiply the downlink share by
  the number of backhaul hops for the worst-placed router.

## Failure behaviour

When a mesh router dies, batman-adv reroutes within a few originator intervals (about 3–5 s with
`orig_interval 1000`). The headsets' TCP connections survive if the relay is still reachable. If
router A (relay + DHCP) dies, headsets fail over to the secondary relay as in
[net-robustness.md](net-robustness.md). Existing DHCP leases last 12 h, so addressing survives
until A is back.
